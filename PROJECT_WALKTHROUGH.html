1. What the system does

The thesis artifact addresses fragmented product discovery by placing several search modalities and the purchase journey in one interface.

T

Text search

Natural-language furniture queries are spell-corrected, embedded by CLIP, and searched against the text index.

I

Image search

One or more reference images are embedded in the same semantic space and searched against the image index.

V

Voice search

The browser records 16 kHz mono WAV; local Whisper transcribes and validates it before search.

AR

3D / AR preview

Products with GLB assets open in Google model-viewer for desktop 3D and supported mobile AR modes.

AI

Optional reasoning

Longer text-plus-image requests can be routed to local Ollama/LLaVA to infer color, category, style, and reasoning.

✓

Purchase & evaluate

A simulated checkout completes the journey; the evaluation page collects research-oriented sessions and surveys.

The primary local runtime is backend/main.py. The repository also contains backend/server.py, a separate clean-architecture experiment. Do not run both on port 8000.

2. Run it locally on Windows

Open two PowerShell terminals from the project root. Python 3.10+ and Node.js 18+ are recommended.

First-time backend setup

cd backend
python -m venv venv
.\venv\Scripts\Activate.ps1
pip install -r ..\requirements.txt
pip install python-multipart openai-whisper

Whisper may need FFmpeg if the browser cannot produce a compatible WAV. The current frontend normally converts recordings to 16 kHz WAV in the browser.

Terminal 1 — start the API

cd backend
.\venv\Scripts\Activate.ps1
python main.py

Terminal 2 — start the interface

cd frontend
npm install
npm run dev

Open these URLs

URLPurpose
http://localhost:3000Main search and shopping interface
http://localhost:3000/evaluationResearch evaluation dashboard
http://localhost:8000Backend status and lazy-load state
http://localhost:8000/docsInteractive FastAPI Swagger documentation
First search is slower. Product data and FAISS indices load on demand, and CLIP downloads/loads on the first search. Voice additionally loads Whisper on first use.

Optional: enable local LLaVA reasoning

ollama pull llava
ollama serve

If Ollama is unavailable, ordinary CLIP/FAISS searches still work; only the extra visual-reasoning metadata is skipped.

4. What happens during a search

1

Capture

The frontend gathers text, multiple images, and optional audio into multipart FormData.

2

Normalize

Audio is transcribed and rejected if it resembles noise. Text is spell-corrected; color is extracted.

3

Encode

CLIP produces normalized 512-dimensional text and image vectors.

4

Fuse

Short text plus images uses 70% text / 30% averaged image; longer text uses a 50/50 balance.

5

Retrieve

FAISS searches the image index when images are supplied, otherwise the text index.

6

Re-rank

Color mismatch receives a soft penalty; matching VLM/category evidence receives a boost.

7

Respond

Top results, metadata, transcription, color filter, mode, and AI summary return as JSON.

8

Act

The user compares results, previews eligible models, adds items, and completes simulated checkout.

Why “soft” color filtering? Incomplete metadata can otherwise produce zero results. The system penalizes non-matches instead of discarding them, then sorts the strongest candidates first.

5. Recommended live demonstration

Use this sequence for a supervisor, examiner, or new developer. It moves from the simplest feature to the complete research workflow.

  1. Health check: open port 8000 and show model/data state before and after the first query.
  2. Text: search modern gray sofa. Explain spell correction, color extraction, CLIP text encoding, and FAISS.
  3. Image: upload a furniture photo without text. Point out visual similarity rather than keyword matching.
  4. Hybrid: keep a sofa reference and type like this but navy blue. Explain weighted fusion and soft color ranking.
  5. Multiple images: upload two inspiration pictures. Their image vectors are averaged before fusion with text.
  6. Voice: record show me a wooden table. Show the returned transcription and search-mode badge.
  7. Optional VLM: with Ollama running, combine an image with a request of three or more words to trigger contextual reasoning.
  8. 3D / AR: select an item marked as having a 3D model. Desktop gives interactive 3D; supported mobile devices can expose AR.
  9. Checkout: add a product, open the cart, enter the guided checkout, and show the generated order confirmation.
  10. Evaluation: visit /evaluation, complete a survey, inspect metrics, and export JSON.

Direct API smoke test

curl.exe -X POST "http://localhost:8000/search/intelligent" `
  -F "query=modern gray sofa" `
  -F "top_k=5" `
  -F "session_id=demo-001"

The four thesis objectives map to: better experience through unified inputs; conversion support through checkout; accuracy/relevance through multimodal retrieval and re-ranking; and satisfaction measurement through the evaluation dashboard.

8. How to evaluate the artifact

  • Create a fixed query set across furniture categories and colors.
  • Run text-only, image-only, voice-only, and combined queries.
  • Record top score, response time, result count, relevance feedback, and add-to-cart action.
  • Ask participants to complete the seven-question 1–5 Likert survey.
  • Export the dashboard JSON for analysis in SPSS, R, or Python.
  • Report dataset imbalance, especially wardrobe (152 items) versus chair (1,814 items).
Research-data warning: the evaluation dashboard seeds realistic demonstration data when local storage is empty. Treat seeded values as UI demonstration data, not empirical participant results. Clear or separately label them before formal analysis.

11. Troubleshooting

“Backend error” in the frontend

Confirm python main.py is running on port 8000. If it uses another host, create frontend/.env.local with NEXT_PUBLIC_API_URL=http://host:port, then restart Next.js.

First search hangs or takes a long time

CLIP is lazy-loaded and may download from Hugging Face the first time. Watch the backend console for [DATA] and [CLIP] messages.

Voice is unavailable

Install openai-whisper, grant browser microphone permission, and speak a short furniture-related phrase. HTTPS or localhost is generally required for microphone access.

Images return broken links

Check that the relative image_path from clean_products.json exists below backend/data/images. The static URL is built from that exact relative path.

AR says the model is unavailable

Confirm the product has has_3d_model=true and that its glb_path exists below backend/data/pix3d/glb. Mobile AR also depends on device support.

LLaVA does not add reasoning

Run ollama serve, ensure the llava model is installed, and submit both an image and a text request of at least three words.

Which backend should I use?

Use backend/main.py for the demonstrated frontend. backend/server.py has a different service stack and response behavior.
